# E1 experiment data

This directory separates runtime code from data collection and paper analysis.
The application writes one directory per protocol run under `logs/`:

```text
logs/<run_id>/
├── run_metadata.json   # configuration, host, camera and controller parameters
├── frames.csv          # one row after perception + command generation per RGB-D frame
├── commands.csv        # every Twist generated by the controller
├── odometry.csv        # raw /odom callback stream
├── events.jsonl        # startup, errors and lifecycle events
├── ground_truth.csv     # template for independent distance measurements
├── operator_notes.md    # template for conditions and abnormalities
├── ros_topics.bag      # optional ROS recording made by record_ros_topics.sh
├── summary.json        # generated by analyze_run.py
├── paper_summary.csv   # one-row table for spreadsheets/paper tables
└── paper_summary.md    # human-readable run summary
```

## Running a safe pilot

The default runtime remains live for backward compatibility. For a pilot that
must not publish velocity commands to the robot, set `MIR_CONTROL_MODE=dry_run`
(`pilot` and `log_only` are aliases):

```bash
cd /home/hung1/robot_mir
export ROBOT_IP=192.168.12.20
export EXPERIMENT_CONFIG=c1_input_capture
export EXPERIMENT_SCENARIO=E1_C1_crossing_visible
export EXPERIMENT_RECORD_RGBD=1
export EXPERIMENT_RUN_ID=pilot_c1_capture
export MIR_CONTROL_MODE=dry_run
docker compose up --build
```

Khi cần lưu ảnh màu/độ sâu gốc để phát lại, đặt tùy chọn trước khi mở ứng dụng:

```bash
export EXPERIMENT_RECORD_RGBD=1
docker compose up
```

Tùy chọn này ghi một tệp cho toàn phiên ứng dụng; run metadata chứa thời gian
đầu/cuối của mỗi lượt đo. Nếu để mặc định `0`, chỉ có các bảng CSV và timestamp.

The container still connects to ROS/MiR so perception, odometry and topic
checks are real, but the application does not publish `/cmd_vel` or send
`move_base` goals in this mode. Before a live run, verify the generated
`commands.csv` has `published=0` and `events.jsonl` has no unsuppressed goal in
the pilot. Only then use `MIR_CONTROL_MODE=live` under a safety procedure.

## Giao diện thu thập dữ liệu C1

Tab **E1 — Hướng dẫn và đo** chia thành hai giai đoạn. Development thu 6
bản ghi nguồn (2 bản ghi cho mỗi nhánh); sau khi hiệu chỉnh và khóa C1, chọn
evaluation để thu 15 bản ghi mới (5 cho mỗi nhánh). Cả hai giai đoạn đều khóa
MiR và lưu RGB-D. Trong hai nhánh cắt ngang, mục tiêu đứng yên ở 2,20 m và
người hỗ trợ đi trước mục tiêu ở khoảng 0,40 m/s. Nhánh che kín dùng thời lượng
0,5/1,5 giây ở development và 0,5/0,75/1,0/1,25/1,5 giây ở evaluation. Đối
chứng tiến lại gần dùng khoảng 0,30 m/s từ 2,0 m tới 1,0 m.

Mỗi bản ghi evaluation được lên kế hoạch replay qua cùng ba profile để có 45
đầu ra ghép cặp. Giao diện hiện chỉ thu bản ghi nguồn; nó không chạy replay và
không đánh dấu 45 đầu ra là đã có. Profile C1 và baseline zero-fallback phải
được triển khai/xác nhận riêng trước khi so sánh.

Cấu hình hàng đợi `c1_input_capture` chỉ ghi RGB-D và lệnh P giả lập hiện tại.
**C1 chưa được áp dụng; MiR bị khóa đứng yên trong mọi lượt.** `frames.csv`
chứa lệnh giả lập; `commands.csv` phải không có lệnh chuyển động thật khác 0.
Đủ log kỹ thuật không có nghĩa sự kiện che khuất đã xảy ra đúng ý định. Giữ mọi
lượt và phân loại mất dấu/nhận lại sau khi xem dữ liệu. Giao diện/metadata
đánh dấu development và tập test giữ riêng; không dùng tập test để chỉnh C1.
Evaluation chỉ mở sau khi đủ 6 bản ghi development đạt kiểm tra kỹ thuật và
người vận hành nhập mã phiên bản/tham số C1 đã khóa.

Các lượt C1 yêu cầu lưu RGB-D gốc; bật `EXPERIMENT_RECORD_RGBD=1` trước khi mở
app. UI chỉ cho hàng đợi chạy khi RGB-D đang ghi và người vận hành đã xác nhận
kiểm tra an toàn cùng nguồn ground truth độc lập liên tục/đồng bộ. Các ô xác
nhận này không tự ghi ground truth; cần video ngoài đã đồng bộ/hiệu chuẩn hoặc
nguồn đo độc lập. Nếu chỉ có mốc khoảng cách rời rạc, không tính lệnh lùi sai
theo thời gian. Kịch bản, số lượt, tiêu chí giữ dữ liệu và chỉ số paper nằm ở
[`paper/E1_data_collection_plan.md`](paper/E1_data_collection_plan.md).

Hàng đợi không chạy `p_original`, `p_no_zero` hay `p_c1` trực tiếp. Sau khi chốt
và triển khai chính xác C1 cùng baseline zero-fallback, phát lại cùng bản ghi
RGB-D qua các cấu hình để so sánh ghép cặp. Không gắn nhãn kết quả capture-only
là hiệu quả C1.

## Recording ROS state

The application opens the RealSense directly through `pyrealsense2`, so RGB-D
images are not ROS topics in the current design. The optional RealSense `.bag`
records the raw color/depth streams for one app session. The ROS bag below
records robot state and commands:

```bash
docker exec -it mir_follower_app \
  bash /app/experiments/scripts/record_ros_topics.sh "$EXPERIMENT_RUN_ID"
```

The per-frame CSV also records frame number, color/depth timestamps and the fact
that depth was aligned to color. If RGB-D recording was disabled, raw images
cannot be reconstructed from those CSV fields.

## Phân tích và xuất bảng cho bài báo

Ứng dụng tự tạo `summary.json`, `paper_summary.csv` và `paper_summary.md` khi
kết thúc lượt đo. Có thể chạy lại công cụ sau khi bổ sung nhãn ground truth:

```bash
python3 experiments/scripts/analyze_run.py \
  experiments/logs/20261117_p_original_E1_crossing_visible
```

Sau khi có nhiều run đã phân tích, tạo bảng so sánh cho paper:

```bash
python3 experiments/scripts/compare_runs.py \
  experiments/logs/run_a \
  experiments/logs/run_b \
  --output experiments/paper/e1_comparison.csv
```

For continuous metrics, preserve `frames.csv`, make a copy named
`frames_annotated.csv`, fill `ground_truth_distance_m` after external
synchronization, and run the analyzer again. Sparse points do not support
continuous reaction-time or false-command metrics.

## Configuration labels

`EXPERIMENT_CONFIG` is stored in the metadata so runs can be compared. The
current Docker application is the operational baseline; it does not yet
implement C1. Do not label a run `p_c1` until the C1 controller is implemented
and verified against the paper's definition.

Protocol thu thập dữ liệu, kịch bản và số lần lặp nằm ở
[`paper/E1_data_collection_plan.md`](paper/E1_data_collection_plan.md).
